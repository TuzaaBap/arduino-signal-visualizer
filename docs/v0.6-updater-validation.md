# v0.6 signed updater validation

Date: 2026-08-12

## Result

The v0.6 signed GitHub updater implementation passes its local automated,
packaging, and installed-application smoke tests. Stable installations accept
only published, non-draft, non-prerelease updates with a complete manifest.

A complete update from one installed version to a newer version remains a
release gate. It requires publishing a signed GitHub prerelease whose
application SemVer is higher than `0.6.0`.

## v0.6 feature boundary

I2C and SPI instrumentation were removed from the v0.6 firmware, protocol
decoder, backend delivery, application tabs, mock source, examples, package,
and release claims pending representative-hardware validation. Packet type IDs
`0x13` and `0x14` remain reserved and are explicitly rejected by v0.6. The Uno
diagram retains its factual SDA, SCL, MISO, MOSI, SCK, and SS pin markings.

Ordinary Arduino sketches may still use the standard `Wire` and `SPI` libraries.
A dedicated compile regression proves they coexist with `ASVInstrumented.h`
without being intercepted or represented as ASV bus telemetry.

## Installed-application smoke test

The installed current-user application launched from
`%LOCALAPPDATA%\Arduino Signal Visualizer`, created a responsive window, showed
application version `0.6.0`, and detected COM6 without opening it.

Mock Mode then ran live GPIO, ADC, and PWM telemetry. During the run:

- the connection remained responsive;
- the manual update check returned **Up to date**;
- the update check did not interrupt Mock Mode telemetry;
- a 20-second memory sample changed working set by -16,384 bytes and private
  memory by -28,672 bytes, with no growth signal;
- disconnect returned the application to its idle state;
- the application closed normally;
- Windows Application Event Log contained no matching application crash.

This is a packaging smoke test, not a replacement for the existing long-runtime
hardware validation.

## Remaining release gate

Before publishing the updater as validated end to end:

1. Publish a draft candidate, then a stable GitHub release for a version higher
   than `0.6.0`
   with its merged `latest.json`, platform bundles, and signatures.
2. Install the preceding application version on Windows and macOS.
3. Confirm discovery, **Skip this version**, **Not now**, signed download,
   installation, restart, and post-update version on both platforms.
4. Confirm a deliberately corrupted or incorrectly signed package is rejected.
